## 算法说明

本系统的核心在于自动调参算法模块（`utils/algorithm.ts`），提供三种阈值优化策略，用于根据监测点历史数据自动计算合理的报警阈值。

### 通用参数

所有算法共享以下输入参数（`TuningParams`）：

| 参数 | 类型 | 说明 |
|------|------|------|
| `algorithm` | `'statistical' \| 'adaptive' \| 'ml'` | 选择的算法类型 |
| `sensitivity` | `number (0-100)` | 灵敏度，值越高阈值范围越窄，越容易触发报警 |
| `historyDays` | `number` | 用于分析的历史数据天数 |
| `confidenceLevel` | `number` | 期望可信度（80-99），用户设定的可信度门槛，与算法输出的"置信度"含义不同 |

算法输出统一为建议的阈值下限（`suggestedLow`）、阈值上限（`suggestedHigh`）和置信度（`confidence`）。

### 算法一：统计学方法（Statistical）

基于经典的 **3σ（三西格玛）原则**，假设监测数据近似服从正态分布。

#### 数学背景

在正态分布 N(μ, σ²) 中，数据落在不同 σ 范围内的概率为：

| 范围 | 覆盖概率 | 含义 |
|------|---------|------|
| μ ± 1σ | 68.27% | 约 2/3 的数据 |
| μ ± 2σ | 95.45% | 绝大多数数据 |
| μ ± 3σ | 99.73% | 几乎所有数据 |

超出 3σ 范围的数据点概率仅为 0.27%，因此可以认为是异常值。本算法利用这一特性，将 3σ 边界作为报警阈值的基准。

#### 计算步骤

**第一步：提取数值序列**

从历史监测数据 `MonitorData[]` 中提取 `value` 字段，形成数值数组 `values`。

**第二步：数据量校验**

若 `values.length < 10`，数据量不足以进行可靠的统计分析，直接返回默认值：
```
{ low: 0, high: 100, confidence: 0.3 }
```
置信度仅为 0.3，提示用户结果不可靠。

**第三步：计算统计量**

```
μ (均值) = Σ(values) / n
σ (标准差) = √(Σ(value - μ)² / n)
```

> 注：此处标准差使用的是总体标准差（除以 n），而非样本标准差（除以 n-1）。当 n 较大时两者差异可忽略。

**第四步：灵敏度映射**

将用户输入的灵敏度（0-100）归一化到 [0, 1]，然后映射为 σ 倍数：

```
sensitivity_normalized = sensitivity / 100
multiplier = 3 × (1 - sensitivity_normalized × 0.5)
```

灵敏度与倍数的对应关系：

| 灵敏度 | 归一化值 | σ 倍数 | 覆盖概率（正态分布下） | 效果 |
|--------|---------|--------|---------------------|------|
| 0 | 0.0 | 3.00 | 99.73% | 最宽松，几乎不报警 |
| 25 | 0.25 | 2.625 | 99.13% | 较宽松 |
| 50 | 0.5 | 2.25 | 97.56% | 中等 |
| 75 | 0.75 | 1.875 | 93.92% | 较敏感 |
| 100 | 1.0 | 1.50 | 86.64% | 最敏感，约 13% 数据会触发报警 |

**第五步：计算阈值**

```
low  = max(0, μ - σ × multiplier)    // 下限不低于 0（物理量非负）
high = μ + σ × multiplier
```

**第六步：计算置信度**

```
confidence = min(0.95, 0.5 + (n / 1000) × 0.3 + (1 - σ / |μ|) × 0.15)
```

置信度由三部分组成：
- 基础值 0.5
- 数据量贡献：`(n / 1000) × 0.3`，数据越多越可靠，1000 条数据贡献 0.3
- 集中度贡献：`(1 - σ / |μ|) × 0.15`，变异系数（σ/|μ|）越小说明数据越集中，贡献越大
- 当 |μ| = 0 时跳过集中度项，避免除零错误

#### 数值示例

假设某温度监测点有 200 条历史数据，统计结果为 μ = 25.0°C，σ = 2.0°C，灵敏度设为 50：

```
multiplier = 3 × (1 - 0.5 × 0.5) = 3 × 0.75 = 2.25
low  = max(0, 25.0 - 2.0 × 2.25) = max(0, 20.5) = 20.5°C
high = 25.0 + 2.0 × 2.25 = 29.5°C
confidence = min(0.95, 0.5 + 0.06 + (1 - 0.08) × 0.15) = min(0.95, 0.698) = 0.698
```

建议阈值范围为 [20.5°C, 29.5°C]，置信度约 70%。

#### 局限性

- 假设数据服从正态分布，对偏态分布或多峰分布效果不佳
- 均值和标准差对极端异常值敏感，少量极端值可能显著拉偏阈值
- 不考虑数据的时间趋势，无法适应渐变型异常

**适用场景：** 数据分布较为稳定、近似正态分布的监测指标，如温度、湿度等环境参数。

### 算法二：自适应方法（Adaptive）

基于 **IQR（四分位距）方法**，对异常值具有更强的鲁棒性。

#### 数学背景

四分位距（Interquartile Range, IQR）是描述数据离散程度的稳健统计量。与标准差不同，IQR 仅依赖数据的中间 50% 部分，天然地忽略了两端的极端值。

在经典的箱线图（Box Plot）异常检测中，通常将 Q1 - 1.5×IQR 以下和 Q3 + 1.5×IQR 以上的数据视为异常值。本算法以此为基础，通过灵敏度参数动态调整倍数。

#### 百分位数计算方法

本系统使用线性插值法计算百分位数：

```
index = (p / 100) × (n - 1)        // p 为百分位，n 为数据量
lower = floor(index)
upper = ceil(index)

若 lower == upper:
    percentile = sorted[lower]
否则:
    percentile = sorted[lower] + (sorted[upper] - sorted[lower]) × (index - lower)
```

例如对排序后的数据 [10, 20, 30, 40, 50]，计算 P25：
```
index = 0.25 × 4 = 1.0 → percentile = sorted[1] = 20
```

#### 计算步骤

**第一步：提取数值序列并校验**

同统计学方法，数据量 < 10 时返回默认值 `{ low: 0, high: 100, confidence: 0.3 }`。

**第二步：计算四分位数**

```
Q1 = percentile(values, 25)    // 第 25 百分位数
Q3 = percentile(values, 75)    // 第 75 百分位数
IQR = Q3 - Q1                  // 四分位距
```

**第三步：灵敏度映射**

```
sensitivity_normalized = sensitivity / 100
multiplier = 1.5 × (1 + (1 - sensitivity_normalized) × 0.5)
```

灵敏度与倍数的对应关系：

| 灵敏度 | 归一化值 | IQR 倍数 | 效果 |
|--------|---------|---------|------|
| 0 | 0.0 | 2.25 | 最宽松，容忍更大的数据波动 |
| 25 | 0.25 | 2.0625 | 较宽松 |
| 50 | 0.5 | 1.875 | 中等 |
| 75 | 0.75 | 1.6875 | 较敏感 |
| 100 | 1.0 | 1.50 | 标准箱线图异常检测倍数 |

**第四步：计算阈值**

```
low  = max(0, Q1 - IQR × multiplier)
high = Q3 + IQR × multiplier
```

**第五步：计算置信度**

```
confidence = min(0.92, 0.55 + (n / 1000) × 0.25)
```

置信度仅与数据量相关，最高 0.92（略低于统计学方法），因为 IQR 方法不依赖分布假设，理论上限更保守。

#### 数值示例

假设某振动监测点有 300 条历史数据，其中包含若干异常尖峰：

```
排序后数据的关键百分位：Q1 = 2.1 mm/s, Q3 = 3.8 mm/s
IQR = 3.8 - 2.1 = 1.7 mm/s
灵敏度 = 50

multiplier = 1.5 × (1 + 0.5 × 0.5) = 1.5 × 1.25 = 1.875
low  = max(0, 2.1 - 1.7 × 1.875) = max(0, -1.0875) = 0 mm/s
high = 3.8 + 1.7 × 1.875 = 6.9875 ≈ 6.99 mm/s
confidence = min(0.92, 0.55 + 0.075) = 0.625
```

即使原始数据中存在 15 mm/s 的异常尖峰，Q1/Q3/IQR 也不会被拉偏，阈值仍然合理。

#### 与统计学方法的对比

| 对比维度 | 统计学方法 (3σ) | 自适应方法 (IQR) |
|---------|----------------|-----------------|
| 分布假设 | 假设正态分布 | 无分布假设 |
| 异常值影响 | 均值和标准差易受极端值影响 | Q1/Q3 对异常值不敏感 |
| 最高置信度 | 0.95 | 0.92 |
| 计算复杂度 | O(n)（一次遍历） | O(n log n)（需要排序） |
| 阈值对称性 | 关于均值对称 | 关于中位数区间对称，可适应偏态 |
| 适用场景 | 稳定正态数据 | 含异常值或偏态数据 |

#### 局限性

- 当数据高度集中（IQR ≈ 0）时，阈值范围会过窄，可能导致大量误报
- 不考虑数据的时间序列特征，无法感知趋势变化
- 对于双峰或多峰分布，Q1/Q3 可能落在不同峰上，阈值可能不合理

**适用场景：** 数据中可能存在异常值或分布不对称的场景，如振动、压力等工业监测指标。

### 算法三：机器学习方法（ML，简化版）

基于 **移动平均 + 趋势分析** 的方法，能够感知数据的变化趋势并动态调整阈值。

#### 数学背景

移动平均（Moving Average）是时间序列分析中最基础的平滑技术，通过对固定窗口内的数据取均值来消除短期波动，揭示长期趋势。本算法在移动平均的基础上引入趋势检测，使阈值能够随数据的整体走向自动调整——这是前两种算法所不具备的能力。

#### 计算步骤

**第一步：数据量校验与降级**

若 `values.length < 20`，数据量不足以支撑移动平均分析，自动降级调用统计学方法 `statisticalTuning()`。这是一种优雅降级策略，确保任何数据量下都能返回有意义的结果。

**第二步：确定移动平均窗口**

```
windowSize = min(20, floor(n / 5))
```

- 窗口大小上限为 20，避免过度平滑丢失趋势信息
- 下限为 n/5，确保至少有 5 个移动平均点用于趋势分析
- 例如：100 条数据 → 窗口 = min(20, 20) = 20；40 条数据 → 窗口 = min(20, 8) = 8

**第三步：计算移动平均序列**

对原始数据按时间顺序，从第 windowSize 个数据点开始，每个位置计算其前 windowSize 个数据的均值：

```
movingAvg[i] = mean(values[i - windowSize + 1 ... i])
其中 i = windowSize - 1, windowSize, ..., n - 1
```

生成的移动平均序列长度为 `n - windowSize + 1`。

示例（windowSize = 3，原始数据 = [10, 12, 11, 15, 14, 18]）：
```
movingAvg[0] = mean(10, 12, 11) = 11.0
movingAvg[1] = mean(12, 11, 15) = 12.67
movingAvg[2] = mean(11, 15, 14) = 13.33
movingAvg[3] = mean(15, 14, 18) = 15.67
```

**第四步：趋势检测**

```
recentAvg  = mean(movingAvg 的最后 10 个值)    // 近期水平
overallAvg = mean(movingAvg 的全部值)           // 整体水平
trend = (recentAvg - overallAvg) / overallAvg   // 趋势因子（相对变化率）
```

趋势因子的含义：

| trend 值 | 含义 | 示例场景 |
|----------|------|---------|
| > 0.05 | 明显上升趋势 | 设备老化导致振动逐渐增大 |
| -0.05 ~ 0.05 | 基本稳定 | 正常运行的环境监测 |
| < -0.05 | 明显下降趋势 | 冬季来临温度逐渐降低 |

**第五步：基础阈值计算**

使用原始数据的标准差 σ 和移动平均的整体均值：

```
multiplier = 2.5 × (1 - sensitivity_normalized × 0.3)
```

灵敏度与倍数的对应关系：

| 灵敏度 | σ 倍数 | 说明 |
|--------|--------|------|
| 0 | 2.50 | 基准倍数，比 3σ 略窄 |
| 50 | 2.125 | 中等 |
| 100 | 1.75 | 最敏感 |

基础阈值：
```
low  = overallAvg - σ × multiplier
high = overallAvg + σ × multiplier
```

**第六步：趋势修正**

这是本算法的核心差异化步骤：

```
若 trend > 0.05（上升趋势）:
    high = high × (1 + trend × 0.5)
    // 上限向上扩展，避免因数据整体上移而产生误报

若 trend < -0.05（下降趋势）:
    low = low × (1 + trend × 0.5)
    // 注意 trend 为负数，所以 low 会减小（向下扩展）

最终: low = max(0, low)
```

趋势修正的效果示例：
```
假设 trend = 0.10（上升 10%），原始 high = 50.0
修正后 high = 50.0 × (1 + 0.10 × 0.5) = 50.0 × 1.05 = 52.5
上限扩展了 5%，为上升趋势留出空间
```

**第七步：计算置信度**

```
confidence = min(0.88, 0.6 + (n / 1000) × 0.2)
```

最高置信度为 0.88，低于前两种方法，因为趋势预测本身存在不确定性。

#### 数值示例

假设某流量监测点有 500 条历史数据，近期流量有上升趋势：

```
原始数据: σ = 5.0 m³/h
移动平均序列: overallAvg = 40.0 m³/h, recentAvg = 43.0 m³/h
trend = (43.0 - 40.0) / 40.0 = 0.075（上升 7.5%）
灵敏度 = 50

multiplier = 2.5 × (1 - 0.5 × 0.3) = 2.5 × 0.85 = 2.125
基础阈值:
  low  = 40.0 - 5.0 × 2.125 = 29.375
  high = 40.0 + 5.0 × 2.125 = 50.625

趋势修正（trend = 0.075 > 0.05，上升趋势）:
  high = 50.625 × (1 + 0.075 × 0.5) = 50.625 × 1.0375 ≈ 52.52

最终阈值: [29.38, 52.52] m³/h
confidence = min(0.88, 0.6 + 0.1) = 0.70
```

对比：如果使用统计学方法（不考虑趋势），上限为 50.63，可能在流量继续上升时产生不必要的报警。

#### 与其他算法的对比

| 对比维度 | 统计学方法 | 自适应方法 | ML 方法 |
|---------|-----------|-----------|---------|
| 时间感知 | 无 | 无 | 有（移动平均 + 趋势） |
| 最低数据量 | 10 条 | 10 条 | 20 条（不足时降级） |
| 最高置信度 | 0.95 | 0.92 | 0.88 |
| 异常值鲁棒性 | 弱 | 强 | 中等 |
| 计算复杂度 | O(n) | O(n log n) | O(n) |
| 核心优势 | 理论基础扎实 | 对异常值免疫 | 趋势自适应 |

#### 局限性

- 移动平均是滞后指标，对突变型趋势反应较慢
- 趋势检测基于简单的近期/整体均值比较，无法识别非线性趋势（如加速增长）
- 窗口大小固定，无法自适应调整
- 仅区分上升/下降两种趋势，阈值为 ±0.05，对微弱趋势不敏感

**适用场景：** 数据存在明显趋势变化的场景，如设备老化导致的振动逐渐增大、季节性温度变化等。

### 辅助统计函数

#### `mean(data: number[]): number`

计算算术平均值。空数组返回 0。

```
mean([10, 20, 30]) = (10 + 20 + 30) / 3 = 20
```

#### `standardDeviation(data: number[]): number`

计算总体标准差。数据量 ≤ 1 时返回 0。

```
数据: [10, 20, 30]
μ = 20
squareDiffs = [(10-20)², (20-20)², (30-20)²] = [100, 0, 100]
σ = √(mean([100, 0, 100])) = √(66.67) ≈ 8.16
```

#### `percentile(data: number[], p: number): number`

使用线性插值法计算第 p 百分位数。先对数据排序，再根据 p 值定位插值位置。空数组返回 0。

```
数据: [3, 7, 8, 12, 15]（已排序）
P25: index = 0.25 × 4 = 1.0 → sorted[1] = 7
P50: index = 0.50 × 4 = 2.0 → sorted[2] = 8
P75: index = 0.75 × 4 = 3.0 → sorted[3] = 12
P37.5: index = 0.375 × 4 = 1.5 → 7 + (8 - 7) × 0.5 = 7.5
```

#### `iqr(data: number[]): number`

四分位距，即 P75 - P25，衡量数据中间 50% 的离散程度。

### 算法选择建议

```
数据特征分析
├── 数据近似正态分布，无明显异常值 → 统计学方法（最高置信度 0.95）
├── 数据含异常值或分布偏态 → 自适应方法（鲁棒性最强）
└── 数据存在时间趋势 → ML 方法（趋势感知能力）
```

按监测类型的推荐：

| 监测类型 | 推荐算法 | 理由 |
|---------|---------|------|
| 温度 (°C) | 统计学 / ML | 通常近似正态分布；若有季节性变化选 ML |
| 湿度 (%) | 统计学 | 相对稳定，正态分布假设成立 |
| 压力 (MPa) | 自适应 | 可能出现突发异常尖峰 |
| 振动 (mm/s) | 自适应 / ML | 异常值常见；设备老化时有上升趋势 |
| 流量 (m³/h) | ML | 常随生产计划变化，存在趋势 |

### 批量调参

系统支持通过 `batchAutoTuning` 函数对多个监测点批量执行调参，内部遍历所有监测点并调用 `executeAutoTuning`，返回每个监测点的调参结果数组。用户可在自动调参页面预览结果后选择性应用。

### 目录说明

#### 核心目录

- **api/**: 封装所有后端接口调用，统一管理 API 请求
- **components/**: 可复用的 Vue 组件，按功能分类
- **stores/**: Pinia 状态管理，支持数据持久化到 localStorage
- **views/**: 页面级组件，对应路由配置
- **utils/**: 工具函数库，包含请求封装、存储管理、算法实现等

#### 关键文件

- **main.ts**: 应用入口，初始化 Vue、Pinia、Router、Element Plus
- **router/index.ts**: 路由配置与守卫，实现登录状态保护
- **stores/user.ts**: 用户状态管理，支持登录持久化
- **stores/monitor.ts**: 监测点数据管理，支持 localStorage 持久化
- **utils/algorithm.ts**: 自动调参算法实现（统计学、自适应、ML）
- **utils/storage.ts**: localStorage 封装，统一数据存储前缀

#### 数据持久化

项目使用 localStorage 实现数据持久化，主要存储：
- 用户登录状态（token、userInfo）
- 监测点数据（monitors）
- 报警配置（alarmConfigs）
- 注册用户信息（registeredUsers）

所有存储的 key 都带有 `alarm_system_` 前缀，避免命名冲突。

**注意**：本项目为演示项目，使用 Mock 数据和 localStorage 模拟后端服务。生产环境需要对接真实的后端 API。
